# 用 Lovable 体验 spsport

适合不想在电脑上输入命令的读者。这里只创建**独立演示项目**，不接入真实会员、数据库或收款。

核对日期：2026-11-01。平台界面会变化，以官方页面和你账号实际显示为准。

## 1. 下载干净的项目 ZIP

1. 回到本仓库首页，点击 **Code → Download ZIP**。
2. 保存下载文件，不要把你自己电脑的整个工作目录重新压缩上传。
3. 特别不要上传 `.env`、客户表格、数据库备份或含个人信息的截图。

GitHub 下载的源代码 ZIP 不包含 `.git` 历史目录；仍应先阅读本项目的 [隐私检查记录](PRIVACY_REVIEW.zh-CN.md)。

## 2. 新建并上传

1. 使用你自己的账号打开 Lovable。
2. 找到 **Upload code** 入口，上传刚下载的 ZIP。
3. 等待创建新项目和预览。
4. 项目名称只填 `spsport`，不要使用员工姓名、客户姓名或真实门店地址。

官方文档区分了两种方式：ZIP 可用于创建新项目；Git sync 是导出与双向同步，不是把任意现有仓库直接导入。参见 [Lovable GitHub 文档](https://docs.lovable.dev/integrations/github#can-i-import-an-existing-github-repo-into-lovable)。

若你的账号看不到 Upload code，不要猜菜单或购买额外服务来碰运气。可先走 [本地体验教程](GETTING_STARTED.zh-CN.md)，或向平台支持确认该账号能使用的导入方式。

## 3. 告诉项目保持演示模式

可以把下面这段文字复制到 Lovable 项目聊天框，它不含任何个人资料或密钥：

```text
请以导入的 spsport 代码为准，先运行演示模式。
不要连接真实数据库、支付账户、短信或邮件服务。
不要添加真实姓名、电话号码、邮箱、地址或任何新场馆品牌。
不要启用支付代码或删除安全关闭逻辑。
请使用 Node.js 22.12+，运行 npm ci、npm run privacy:check、npm test 和 npm run build。
如果检查失败，请说明失败的位置，修复后再生成预览。
```

**成功标志：页面出现 spsport 和演示视角切换，未要求输入付款密钥。**

## 4. 完成一笔演示操作

按 [新手教程第 5 步](GETTING_STARTED.zh-CN.md#5-按这个顺序体验一次) 选择日期、场地、时段。只使用 `guest001@example.com`。结果应提示没有扣款、没有保存预订。

不要把演示成功理解为数据库或支付已经配好。

## 5. 发布演示

确认检查通过且仍处于演示模式后，再使用项目的发布入口。选择访问范围时，先用仅自己可见的预览核对；确认页面只有示例数据后，再决定是否公开分享。

发布以后重新打开链接检查：spsport 品牌、演示提示、中文、手机布局和子页面刷新。不要仅凭聊天框说“完成”就认为网站已经正确发布。

## 6. 内置后台不是自动接好本项目

Lovable 提供数据库、认证、Secrets 和 Edge Functions 等内置后台能力，但导入代码不等于本项目的数据表、权限、迁移和环境变量都已配置正确。是否启用还取决于项目和权限设置。参见 [官方后台说明](https://docs.lovable.dev/features/cloud)。

需要保存测试数据时，先按 [测试数据库说明](../LOVABLE_DEPLOY.md) 理解建表、权限和验收。使用内置后台也要逐项核对。不要为了“让报错消失”把服务端密钥改成 `VITE_` 变量，不要复制真实数据库到演示项目。

## 7. 公开代码的额外注意

Lovable 的 Git 提交可能带有操作者的关联邮箱或提交归属信息。准备公开代码前，在 GitHub 检查提交详情，并按 [安全说明](../SECURITY.md) 使用隐私身份；不要只检查页面上有没有姓名。官方说明见 [提交归属](https://docs.lovable.dev/integrations/github#are-commits-made-by-lovable-attributed-to-me)。
